# Geometry-round metric boundaries

The published v20 LongBench captured state `8fa2b3a5b4c4` (mpk) reached 16 naturally occurring denoising calls. **Sum of separately timed complete decoder-forward spans divided by16**, in ms/call: native **163.494**, M1-R1 **161.852**, M3-R2 **156.934**, M3-R3 **155.474**, B_A8 **152.487**. R3/native is 0.9510 (about 4.9% lower) on this replay. These are full model/logits forward spans including in-forward routing and current attention; they exclude the outer sampler/stop/T bookkeeping, initial prefill and later commit. The direct sequence epoch includes snapshot/RNG restoration and is a different boundary. A CUDA event span may include host submission gaps; it is not GPU-active time. Three axes stay separate: generation canvas is 256 tokens; the support **decision** unit is old GLOBAL GQA8heads×Q2×KV32 or LOCAL2heads×Q8×KV32 versus current per-head Q128×KV64; the current physical sparse **execution** program is already per-head Q16×KV64 and shares its bitmap with seven siblings. Thus a Q16 compute tile is not evidence of a Q16 decision. [Geometry crosswalk](legacy_geometry_crosswalk.md).

For the next opportunity card, report actual A/D/H and native/fresh/matched complete attention calls; direct decoder-forward and denoising-step prices on common Q/K/V/history; separately initial-prefill and clean request wall; scoped legal-pair QK/PV skip, K/V loads, bitmap/summary bytes and route/copy time. Whole-request work needs actual calls **and** canvases/output tokens because adaptive completion can change. Pair ratios within host; do not pool absolute ms across GPUs. An optimistic arithmetic screen from observed v20 LB work requires R3/native per-call cost below `2360/2514 = 0.9387` merely to offset call inflation under equal-cost assumptions; the actual request can differ with context and other work. No old 1.178× generation ratio or single 4–9% captured-forward ratio is a forecast for the new geometry.
