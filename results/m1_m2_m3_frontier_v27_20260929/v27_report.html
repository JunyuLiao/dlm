DiffusionGemma 稀疏注意力 v27 报告

M1 / M2 / M3 在原生自适应停止下的实验汇总，2026-09-29。模型为 DiffusionGemma-26B-A4B（BF16，H100）。GLOBAL 层是第 5、11、17、23、29 层，共 5 层，head_dim 512；其余 25 层是 LOCAL 层，滑动窗口 1024，head_dim 256。代码和数据在分支 research/m3-output-numerics-20260927 的 results/m1_m2_m3_frontier_v27_20260929/。

结论
  • 和最强 dense 相比，目前的稀疏方法在单次 forward 上没有收益。在 14–17K 上下文下，把稀疏 kernel 修到最好之后，同 kernel 的 dense 是 native 的 0.896–0.907，最好的稀疏变体是 0.895–0.916，两者打平。
  • 之前报的"比 native 快 8–10%"不是稀疏带来的。native 的 GLOBAL attention 调用走了 SDPA 的慢路径（enable_gqa，5.24 ms）。换一种 dense 调用方式，就能单独拿到这部分提速。
  • 根因有两层。第一，旧稀疏 kernel 效率只有 SDPA 的一半：每 16 行 query 重读一遍 K/V。已修复，新 kernel 在 dense 时快 37%。第二，在 16K 下，用好 kernel 算的 GLOBAL attention 只占 forward 的约 5%，其余是 MoE、FFN 和 LOCAL 层，跳块的上限就这么多。
  • 还成立的结论：跨层共享 bitmap 能把选块开销压掉大半。LOCAL 层稀疏不可行。短上下文（AIME、RULER-4K）没有可省的 attention。原生自适应下，主候选 M3 的 AIME 质量不下降。
  • 下一步是长上下文（32K–128K）。attention 占比会升到 19–30%，稀疏的天花板随之升高。

3. 为什么跳了 60–70% 却没快

3.1 dense 基线本身有 2 倍空间

模型原生的 GLOBAL attention（16 个 query 头、2 个 KV 头、head_dim 512）走的是 SDPA 的 enable_gqa 路径，要 5.24 ms。同样的计算先把 KV 复制成 16 个头再调 SDPA，只要 2.33 ms。之前所有"相对 native"的收益里，这一块占了绝大部分。

3.2 旧稀疏 kernel 效率只有 SDPA 的一半

旧 kernel 每个程序只处理 16 行 query。一个 canvas 有 256 行，按 16 行切成 16 个程序，同一个 KV 头又被 8 个 query 头共用，所以每个保留下来的 K/V 块在一层里要读 16 × 8 = 128 次。16 行的矩阵乘也用不满 tensor core。结果是全保留时要 4.48 ms，而 SDPA 只要 2.36 ms。

新 kernel 改成每个程序处理 64 行，再沿 KV 方向切 2 份来补足并行度。bitmap 语义不变：它按 Q128 分块，两个 64 行块正好共用同一行。与 dense 参考答案的最大误差约 1e-3。

3.4 和以前 FIXED16 G75/L30 约 10%、BLASST 20% 稀疏度就回本的区别

  • FIXED16 G75/L30：在 vLLM 运行时里测，dense 基线是当时 vLLM 的 TRITON_ATTN 内核，用的是固定 16 步，LB 输出上限 1024。它没有和"最强 dense kernel"比过。head_dim 512 下，那个 dense 内核很可能也有类似的效率问题，所以那 10% 同样需要用最强 dense 重新检验。
  • BLASST：用在 LLaDA 上，每层都是全局 attention，head_dim 128，而且使用的就是它自己的高效 FlashAttention 式内核。attention 在 forward 里的占比远高于 DiffusionGemma（这里只有 5 层 GLOBAL，其余是 MoE），所以 20% 稀疏度就能回本。

6. 要不要挪到 vLLM，下一步怎么做

判断：现在不挪。单次 forward 的上限取决于 attention 在 forward 里的占比，和用哪个推理框架无关。vLLM 只会让 dense 基线更强，16K 下的上限还是约 5%。vLLM 或 SGLang 的价值在论文最后的系统评测：真实服务系统里的端到端吞吐。所以等长上下文的收益确认之后，再移植最终方法。

让论文有说服力的做法

  • 主战场放在长上下文：RULER 32K/64K/128K，加 LongBench v2 的长题（少截断）。模型支持 128K 上下文。按实测估算，GLOBAL attention 在 64K 时约占 forward 的 19%，128K 时约 30%。70% 稀疏度下，预计单次 forward 在 64K 省 10–13%，128K 省约 20%。选块开销基本不随长度增长。
  • 基线用最强的：同 kernel dense（D_c64）、SDPA repeat_kv、fresh T（相当于 SparseD 的每步重选）、B（沿用 bitmap）。所有收益都相对最强 dense 报。
  • 方法贡献可单独识别：历史 QK 加当前 V 的周期性重选（M3），再加跨层共享 bitmap 摊薄选块开销。对 R、A、共享方式、稀疏度分别做消融。
  • 质量两张表：一张是长上下文的正确率对稀疏度扫描曲线；另一张是短上下文（AIME、GSM8K/MATH-500），要求不下降，长度开关在短上下文直接走 dense。
  • 速度报三层：kernel 随上下文长度的扩展曲线、单次 forward、整请求，同时报总步数和 canvas 数。

第一步（约半天）：先在 32K/64K/128K 上只测 kernel 和单次 forward，验证"收益随长度放大"这个判断。成立再做质量和整请求；不成立，这条路就到此为止。
