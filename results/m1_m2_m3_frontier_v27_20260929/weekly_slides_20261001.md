**【要点】**
- 用 6 个新 seed 后，**每 canvas 步数 0.97–1.03、输出长度 0.95–1.01：步数不再增加**。此前 3 个 seed 时看到的"留出题上输出长 18%"是轨迹噪声。

- 原版 M1/M2c/M3 在两档都比 dense 慢（1.06–1.34 倍）：选块和观测的开销超过省下的注意力。

## 第 2 页：时间都花在哪：为什么单请求下注意力稀疏的收益有上限

**【正文顶部】** 64K dense 一个请求约 13.1 s（三台 H100、piecewise_v3–v5 实测平均）；32K 约 9.7 s

**【主表】（64K，占请求时间）**

| 部分 | 时间 | 占比 | 稀疏注意力能否省 |
|---|---:|---:|---|
| prompt prefill + 准备 | 约 4.6 s | 35% | 否（不在本方法范围） |
| 解码：5 个 GLOBAL 注意力层 | 约 2.8 s | 21% | **是**：M3 降到约 1.2 s |
| 解码：MoE 专家 | 约 2.4 s | 18% | 否（每步读约 46 GB 专家权重，已到 HBM 带宽上限） |
| 解码：采样（262K 词表） | 约 0.9 s | 7% | 否 |
| 解码：其他（投影、LOCAL、norm、canvas 追加） | 约 2.4 s | 19% | 否 |

**【要点】**
- 即使注意力完全免费、步数不变，单请求的上限也只有 64K 约 −21%、32K 约 −16%；我们已拿到 −12% / −6%。
- M3 剩下的约 1.2 s 注意力（估计）：每个 canvas 前 2 个 dense 步约 0.5 s、稀疏执行约 0.5 s、观测/决策约 0.2 s。
- AIME（上下文 ≤ 约 8K）上 GLOBAL 注意力只占每步约 4–7%：注意力稀疏在 AIME 上天然没有多少空间。

**【Speaker notes】**
- 每步构成（32K，dense，`substrate/time_breakdown.json`，v2 时期，KV 拼接已在 v3 去掉）：forward 约 32 ms：MoE 专家矩阵乘 12.8 ms、GLOBAL 注意力 7.2 ms、其余矩阵乘 3.5 ms、LOCAL 0.8 ms、其他约 4 ms；加上采样约 4.6 ms。
- MoE：128 个专家、每 token 选 8 个；一步 256 个 canvas token × 8 = 2048 次分配，几乎所有专家都会被用到，所以每步要读全部专家权重（约 46 GB），12.8 ms 已接近 H100 的 HBM 带宽极限。
- GLOBAL 注意力（CUDA event 直接计时，`kernel_bench/module_profile_*`）：dense 每层 1.46 ms（32K）/ 2.95 ms（64K）；M3 R6 DP −ln2 摊到每步：32K 4.3 ms、64K 5.5 ms（dense 7.3 / 14.75 ms）。
- 每步解码时间（摊销，72 格平均）：32K dense 37.3 ms、M3 34.7、B 33.5；64K dense 45.3、M3 37.2、B 36.1；AIME dense 30.7、M3 31.4。

## 第 7 页：相关工作与新颖性现状

**【主表】**

| 工作 | 做法 | 设置 | 与我们的关系 |
|---|---|---|---|
| SparseD（ICLR 2026, 2509.24014） | 前若干步 dense，之后按池化分数选块并复用 | LLaDA/Dream，固定步数，无 KV cache | ≈ B，撞车；FA4 同 kernel 正面对比速度无显著差别 |
| MAGE（2602.14209） | 块的第一步做精确注意力选 top-k，整块复用；副流异步选块 | 7–8B 块扩散，32 token 块 × 固定 32 步，128K 端到端 6.82× | ≈ B（撞车）；大倍数来自 dense 小模型 + 128K + 固定步 |
| PulseCol（2605.20813） | 列稀疏，早期周期刷新 | 1024 步固定 | ≈ M3 的定期刷新 |
| HERALD（2606.21633） | 批量块扩散服务：每块选一次 KV、CPU-GPU 协同取 KV | 批量服务，5% KV 预算，解码吞吐 2.28× | 批量服务方向的直接相关工作 |
| Focus-dLLM、LoSA、FlashBlock | 按置信度/稳定 token 裁剪或复用 | 固定步数/长度 | 部分相关 |
| Lil（2601.03043）、LessIsMore（2508.07101） | 稀疏注意力导致推理输出变长 | 自回归推理模型 | 我们在 E4 中没有观察到输出变长 |

**【要点】**
- 方法层面"每块选一次、复用"的思路已被 SparseD / MAGE / HERALD 覆盖；"看 V 的选块更好"没有数据支持（AIME 高稀疏度下反而更差）。
- 我们站得住的是：生产级 MoE dLLM（DiffusionGemma，原生自适应停止 + KV cache）+ 最强官方基线（FA4 + CUDA graph）+ 大样本协议下，端到端 64K −12%、32K −6%，精度不降；以及"MoE 权重带宽决定上限"的成本分析。
- 可能的论文方向（待讨论）：(1) 批量服务（需先看第 6 页的测速；HERALD 部分撞车）；(2) 自适应停止下 dLLM 加速的评测方法学（大样本、dense 对照方差）；(3) 与同学的 query 敏感度方向合作。
