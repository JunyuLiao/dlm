## Frozen design

- E14 eligible LongBench-v2 items: 24 at 32K, 24 at 64K, 11 at 96K; four repeats.
- Primary: dense default graphs vs main PIECEWISE. Native-hook PIECEWISE and alias-split
  all-kept controls on four items per bin, all repeats. Both controls share the adapter
  deployment; increment over these standard execution changes is shown separately.
- Single host per cell. Two engine seed blocks, each containing two repeats. Counterbalanced
  arm-block order; identical item order within a block. Engine seeds are recorded, but
  repeats do not claim seed-paired diffusion trajectories.
- Warm every selected item once per fresh engine, before timing. Reject new timed CUDA
  graph captures and backend/inductor compilations. Keep failed records, relaunch into a
  new directory; never append a replacement to an old run.
- 96K preflight uses the longest eligible prompt and identical memory 0.92, max length
  106496, chunked prefill 16384, block size 32 (GLOBAL page 64), batch 1. A failure is a
  serving limitation of that spec, not grounds for selectively discarding the item.

## Measurement correction

The smoke runner synchronizes after each engine step and estimates prefill as ceil(tokens /
chunk). Its step list contains encoder commits as well as denoising. Those smoke figures
remain previews. The formal worker counts real scheduler phases from existing CPU sampled
token lists, adds no GPU operations for counting, and synchronizes only at request boundaries.

W includes prefill; S starts at the last prefill scheduler completion and includes canvas
commits. N counts denoising forwards only; commit forwards are reported separately. S/N is
amortized per denoising step, not direct kernel latency. No HTTP/network time is included.
Adapter per-request initialization and cleanup are charged to W. All 112 CPU qualification
tests passed in the registered research interpreter before freezing.

## Integrity, scoring and reporting

The public spec precedes generation. Private freeze/bind records pin the spec, deploy,
adapter/core sources, model generation config, eligible manifest copies and config. Raw
token sequences, prompts, answers and their hashes are never published. Raw completions
are decoded privately with special tokens retained so the existing v15 final-channel NeMo
scorer is unchanged. No fallback extraction from the thinking channel is allowed.

Each method receipt must match frozen effective_method, five GLOBAL layers, one begin and
observe per denoising forward, zero clock errors and native fallbacks, and positive fused
observation / decision / split-consumer counters. The scoreboard rejects duplicate or
missing executions, mismatched host/GPU/deploy/settings and unknown/nonzero graph counts.

Report W, S, S/N, N, correct counts, paired geometric means and question-clustered bootstrap
95% intervals. Pairing is by item and repeat label, not by stochastic trajectory. Accuracy
differences also use question clusters; McNemar is exploratory because repeats share items.
Four repeats are the initial frozen panel, not a guarantee of a conclusive CI or noninferiority.

GPU reserved seconds include worker loading, warmup, generation and failed attempts; this
is an allocation-time accounting measure, separate from request wall time.
