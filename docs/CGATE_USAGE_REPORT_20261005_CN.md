# C gate 在 DiffusionGemma 长上下文稀疏 attention 中的使用情况（2026-10-05）

数据在分支 `research/v31-progress-aware-20261004`：`docs/V31_BASELINE_ROOT_CAUSE_20261003.md`，以及 `results/v31_20261003/panels/`。

## 1. 背景：我们的方法和 C gate 能插在哪里

- **设定：** DiffusionGemma-26B，vLLM + FA4，H100，32K–128K 上下文。每个 canvas 256 行，官方采样器自适应停止（最多 48 步）。
- **稀疏方式：** 只稀疏 5 个 GLOBAL 层的前缀 attention，预算 8192 token。
  - 每个 canvas 第 1 步做一次精确观测，按"每个 head × 128 行块"选相同数量的 KV tile（保证 GPU 负载均衡），之后保持这份选择。
  - 中途在某个时机重新观测一次整个前缀并重选；重选时已选 tile 有加分（"粘性"），避免一次换掉太多。
- **C gate 可以插的位置：**
  1. 时钟：决定何时重看；
  2. 行权重：重选时偏向哪些行；
  3. 停止规则：canvas 何时结束；
  4. 救援：停滞时临时退回 dense；
  5. 预算：重选时用多少预算。

## 2. 实现（与参考实现 `value_direction_hopper/query_adaptive.State` 逐项对齐，CPU 测试确认数值完全一致）

每个 canvas 行，每步更新：
- q = γ·q + (1−γ)·(1 − accepted)，γ = 0.65，初值 1：被重新加噪（未被接受）的指数平均；
- r = (r + 1)·accepted，argmax 一旦改变就清零：连续稳定被接受的步数；
- u = √(1 − p_top)：不确定度；
- 已定程度（settledness）= (1 − e^(−r/τ))·(1 − q)·(1 − u)，τ = 2.5，取值在 [0, 1]；
- 敏感度权重 s = clip(1 + β(1 − settledness), 1, 1 + β)，β = 3。

**"已接受"（accepted）的含义：** DiffusionGemma 官方采样器每步把 canvas 的 256 个位置按 token 熵从小到大排序，依次接受，直到"累计熵 − 当前最大熵"超过熵上限为止。被接受的位置取 argmax；其余位置重新加噪，下一步再预测。我们从采样器同一份 logits 重算这个 mask，规则完全相同。

**"已接受比例"** = 当前这一步被接受的行数 / 256。它随去噪推进从接近 0 涨到接近 1，是对照用的另一种时钟。

## 3. 各种用法的结果（S1 子集：RULER 78 / LongBench-v2 32 / MRCR 24 / GraphWalks 12 题 × 2 seed；官方评分）

**公平性的共同条件：**
- 同一模型、同一部署；
- 每个 cell 的所有方案在同一台机器上跑；
- 同题同 seed；
- 同一个 KV 预算（除非另外注明）。

### 3.1 作时钟（何时重看）：可用，与"已接受比例"打平

条件：两者都用 8192 预算、带粘性、加 FA4 修复。准确率、步数、时间都来自同一批运行；时间相对修复后的 dense。

| 数据集 | 时钟 | 准确率 | 总步数 | 每 canvas 步数 | 单步耗时 | 纯 decode 时间 | 端到端时间 |
|---|---|---|---|---|---|---|---|
| LongBench think | dense | 43.8% | 19,390 | 19.4 | 32.8 ms | 1 | 1 |
| | 已接受比例 ≥ 0.5 | 48.4% | 18,688 | 19.7 | 24.5 ms | 0.72 | 0.81 |
| | C gate 已定程度 ≥ 0.15 | 46.9% | 17,460 | 19.5 | 24.2 ms | 0.66 | 0.77 |
| GraphWalks | dense | 0.367 | 20,716 | 10.7 | 27.7 ms | 1 | 1 |
| | 已接受比例 | 0.362 | 18,484 | 9.0 | 25.4 ms | 0.82 | 0.83 |
| | C gate | 0.370 | 21,886 | 10.4 | 24.0 ms | 0.92 | 0.92 |
| MRCR | dense | 0.391 | 1,125 | 13.7 | 29.1 ms | 1 | 1 |
| | 已接受比例 | 0.381 | 886 | 12.1 | 28.8 ms | 0.78 | 0.95 |
| | C gate | 0.393 | 867 | 11.9 | 28.8 ms | 0.77 | 0.94 |
| RULER | dense | 88.94 | 770 | 4.9 | 41.5 ms | 1 | 1 |
| | 已接受比例 | 89.55 | 769 | 4.9 | 43.3 ms | 1.04 | 1.00 |
| | C gate | 89.29 | 791 | 5.1 | 44.0 ms | 1.09 | 1.005 |

两种时钟实际在第几步触发（"相对位置" = 平均触发步 / 每 canvas 平均步数）：

| 数据集 | 已接受比例：平均触发步（相对位置） | C gate：平均触发步（相对位置） |
|---|---|---|
| RULER | 1.1（22%） | 2.1（41%） |
| MRCR | 4.9（41%） | 6.2（52%） |
| GraphWalks | 5.7（63%） | 6.0（57%） |
| LongBench | 11.8（60%） | 8.9（46%） |

**解读：**
- 两种时钟准确率都与 dense 持平，总体速度打平：两个长输出任务合并，端到端 0.816 vs 0.830。
- C gate 的触发位置在不同任务间更一致（41–57%）。"已接受比例"在短答案任务上几乎第 1 步就触发：末尾的结束符位置一开始就被接受，把比例抬了上去。
- 但更一致的触发没有转化为更好的结果。差别都在小样本噪声内（同配置重跑一次，端到端会变约 ±0.05）。

**比较的局限：**
- 两个阈值（0.5 和 0.15）都是手选的，没有对两者做同等程度的调参。所以这是两个具体配置的比较，不是两种信号的最优比较。
- 两个 dense 参照中，LongBench 是在 03:38–04:00 UTC 跑的，其余三个是 05:15–05:37 UTC；同机器、同 cell。各时钟方案都对照同一数据集上的同一组 dense。

### 3.2 作重选的行权重：在测试过的配置下有害

**配置：** 4096 预算、"已接受比例 ≥ 0.5"触发、无粘性、不加修复。权重用的是简化版：只看"本步未被接受"的行，不是完整的 C gate 已定程度。对比的是同一配置下加权与不加权，其他条件全部相同。

| | RULER | LongBench | MRCR | GraphWalks |
|---|---|---|---|---|
| 准确率（相对 dense）：不加权 | +0.10 | 0.0 | −0.028 | −0.096 |
| 准确率（相对 dense）：加权 | −0.06 | −6.3 分（不显著） | −0.021 | −0.044 |
| 每 canvas 步数（相对 dense）：不加权 → 加权 | — | 0.95 → 1.00 | 1.06 → 1.06 | 0.89 → **1.23** |
| 总步数（相对 dense）：GraphWalks | — | — | — | 1.24 → **1.45** |
| 端到端（相对官方 dense，两者都不加修复）：不加权 → 加权 | — | 0.75 → 0.88 | 0.97 → 0.97 | 1.16 → 1.27 |

- 固定 canvas 诊断（每个 canvas 从同一前缀和噪声出发，只看 attention 的影响）：每 canvas 步数，不加权 1.013，加权 1.033。
- 更早的一轮（RULER / MRCR）里，query 敏感度系列权重（conf、margin、temporal 及组合）也都没有超过不加权的重选。
- **可能的原因：**
  - 预算固定，加权只是在行之间"重新分配"。偏向未定的行，就会把已定行依赖的上下文挤掉。
  - 但已定的行并没有真正固定：每步仍会重新判定是否接受，argmax 也可能翻转。而且 canvas 内部是双向 attention，已定行的表示会影响其他行。
  - 上下文被抽走后，这些行被重新加噪，导致输出变长、步数变多。GraphWalks 这类多跳推理最明显。
- **还没测的（已在队列中，结果出来后补充）：**
  - 完整的 C gate 权重 s = 1 + β(1 − 已定程度)；
  - 在最终配置（8192、带粘性、加修复）下的加权版本。

  所以"有害"这个结论目前只适用于上面那个配置。

### 3.3 作停止规则：从未触发

- 规则：每一行都连续 R = 3 步稳定被接受，就提前结束 canvas。
- 固定 canvas 的 518 个 canvas、9,022 次检查里一次都没触发：官方的收敛判据（平均熵 < 0.005 且 argmax 稳定）总是更早满足。
- 而且它会改变解码本身，与 dense 对比不公平。所以已放弃，不放进主比较。

### 3.4 作停滞救援（已定程度停滞时，GLOBAL 层退回 dense）

- 固定 canvas、同一 dense 参考轨迹下，每 canvas 步数相对 dense：不救援 1.037，停滞 3 步即救援 1.025，第 20 步救援 1.033。
- 效果很小。

### 3.5 预算随进度递减（重选时的预算 = max(下限, K·(1 − 进度))）

**配置：** 与 3.2 相同（含简化版行权重）。要单独看"预算递减"的影响，应与同样带权重、但预算不变的版本对比。

| | 预算不变（4096） | 降到 2048 | 8192 降到 2048 |
|---|---|---|---|
| RULER 准确率（相对 dense） | −0.06 | −0.90 | −0.67 |
| MRCR 准确率（相对 dense） | −0.021 | −0.099 | −0.007 |

降到 2048 把重选带来的 MRCR 收益丢掉了，也不省时间，已否决。

## 4. 小结

| 用法 | 结论 |
|---|---|
| 时钟（何时重看） | ✅ 可用，与"已接受比例"打平，跨任务的触发位置更一致；暂作最终方法的时钟 |
| 行权重 | ❌ 在测试过的配置（4096、无粘性、简化权重）下有害；完整版和最终配置待测 |
| 停止规则 | ❌ 从未触发（官方收敛更早） |
| 停滞救援 | ➖ 效果很小 |
| 预算递减 | ❌ 掉点 |

## 5. 可能的改进方向

1. **从"重新分配"改成"保护"：** 不改变各行的预算分配，而是在固定预算之外，给"未定且高敏感"的行额外加少量它们最需要的 tile，或者保证已定行的关键 tile 不被换掉。这样敏感度信息只加不减。
2. **让 C gate 决定"要不要重看"：** 现在每个 canvas 固定重看一次。短 canvas（RULER 约 5 步）上，重看的开销摊不开，单步比 dense 慢 4–9%。如果能判断"选择还没过时、不需要重看"，就能省掉这次开销。反过来，长 canvas 停滞时允许第二次重看。
3. **时钟阈值的标定：** 0.15 是手选的。是否有更有原则的阈值，比如按 canvas 自身的进度曲线（相对值），或者按已定程度的变化率？
4. **哪些行真的"定了"：** 第 3.2 节说明"被接受"不等于"定了"（行仍会被重新加噪、argmax 会翻转）。能否更准地预测"之后不会再变"的行？这对行权重和"稳定行复用"类方法（如 LoSA）都有用。
5. **和 value-aware 选块结合：** value-aware 跳块可以作为选块打分的一部分，在同底座下（同 kernel、同预算）对比。
